# Bewly_Nocturne

Bewly_Nocturne 是一个面向个人使用习惯定制的 Bilibili 浏览器扩展。它仍是浏览器扩展，不是 macOS、桌面或移动客户端。

## 来源与维护

Bewly_Nocturne 基于 [BewlyCat](https://github.com/keleus/BewlyCat) 开发；BewlyCat 基于 [BewlyBewly](https://github.com/BewlyBewly/BewlyBewly)。本仓库保留原项目历史和贡献者信息。

本项目会继续选择性合并 BewlyCat 上游更新。无冲突的更新正常接收；与 Bewly_Nocturne 定制行为冲突时，经人工审查后保留本地定制。

维护者的分支、Fork、cherry-pick 与上游同步流程见[上游协作流程](docs/maintenance/upstream-workflow.md)。

本项目仅接受外观和视觉交互的issue，底层功能请向上游提交。

本项目假设用户有超过平均线的运行设备，故任何性能和外观之间的取舍都会偏向于外观。

## 夜曲设计一览

Bewly_Nocturne 并不是 BewlyCat 的纯镜像。它在保留 Bilibili 内容能力的基础上，维护一套独立的夜曲视觉与交互设计：

| 区域 | Bewly_Nocturne 的设计 |
| --- | --- |
| Dock | iOS 风格完整胶囊；未选中项没有圆形底板，选中指示、Hover 发光和刷新后居中保持连贯；浅色使用主题色光晕，深色使用白色发光选中效果。 |
| 页面与顶栏模式 | 支持“全 Bewly / 全原版 / 自定义”；顶栏类型在 Dock 内容设置中配置，不作为导航项。全原版会尊重 Bilibili Evolved 顶栏。 |
| 毛玻璃 | 默认开启，模糊强度全局统一。一个“关闭毛玻璃与顶栏渐变”选项即可切换到完整实色版本，不维护彼此冲突的多个开关。 |
| 深色网页背景 | 使用 OKLCH 限制最终明度和色度，让不同深色基准色仍保持稳定、舒适的页面底色，同时保留轻微色相倾向。 |
| OLED 纯黑 | 仅在实际深色主题下把网页底层变为 `#000`，卡片、面板和弹窗继续保留层级，不以覆盖原站布局的方式实现。 |
| 平滑圆角 | 卡片、面板、输入控件和媒体使用统一的连续曲率；圆形按钮、头像、Switch 和完整胶囊仍保持真实 round。浏览器不支持 `corner-shape` 时自动使用原有 `border-radius`。 |
| 表面与边框 | 深色玻璃表面使用克制的透明层级和不透明边框；设置页、Dialog、Popover 与媒体外框遵循同一套语义 token。 |
| 设置体验 | 设置窗口从实际 Dock 按钮位置展开；顶部渐变模糊自然衰减且不影响清晰外框；关闭按钮、标签删除按钮和普通圆形操作具有清晰且独立的组件语义。 |
| 设置归类 | 毛玻璃与普通顶栏渐变由一个负向开关统一控制；主题色渐变只在外观中配置；内存节省选项集中在“通用 → 内存节省”，不重复入口。 |
| 主题色可读性 | 实色主题背景上的文字与图标会根据最终主题色亮度自动选择黑色或白色，近白主题色也能保持清晰。 |
| 精简功能 | 背景图片功能已完整移除；项目不保留壁纸入口、存储字段、渲染层或旧数据兼容代码。 |
| 运行稳定性 | 扩展重新加载和消息通道失效使用统一处理；开发内容脚本保留可读函数名，避免长期增量编译产生调用错配。 |

这些设计属于 Bewly_Nocturne 的维护边界。选择性合并 BewlyCat 上游更新时，会逐项审查 Dock、顶栏、页面模式、主题、圆角、毛玻璃和设置交互；上游实现不会直接覆盖这些本地设计。

更具体的实现约束和冲突审查基线见 [AGENTS.md](AGENTS.md)。

## 本地构建

```sh
pnpm install
pnpm dev
```

开发模式不会压缩内容脚本，以保证长时间监听编译时的函数引用稳定；生产构建仍沿用正常压缩流程。重新编译或重载未打包扩展后，已有 Bilibili 页面需要刷新一次以接入新的扩展上下文。

Chrome 生产版及 ZIP：

```sh
pnpm build
pnpm pack:zip
```

构建目录为 `extension/`，压缩包为 `extension.zip`。
